## Описание модуля фитнес-трекера (версия 2.0)

На основе полученных знаний о структурах, методах, встраивании и интерфейсах мы полностью переработали архитектуру фитнес‑трекера. Логика теперь распределена по пяти независимым пакетам, каждый из которых отвечает за свою предметную область. Вместо набора разрозненных функций мы используем **структуры** для хранения данных пользователя и тренировок, **методы** для парсинга и формирования отчётов, а **интерфейс** позволяет унифицированно обрабатывать разные типы активностей (прогулки и тренировки). Это делает код гибким, расширяемым и удобным для сопровождения.


## Общая архитектура

Модуль состоит из пяти пакетов:

1. **`spentenergy`** – расчёты средней скорости, дистанции и затрат калорий для бега и ходьбы.  
2. **`personaldata`** – структура с персональными данными пользователя (имя, вес, рост) и метод для их вывода.  
3. **`trainings`** – обработка строк с данными о тренировках (бег/ходьба), хранение и формирование детального отчёта.  
4. **`daysteps`** – обработка строк с данными о прогулках, хранение и формирование краткого отчёта.  
5. **`actioninfo`** – интерфейс и функция для единообразной обработки любых активностей, реализующих этот интерфейс.

Основная функция `main()` не изменяется – всё управление делегируется этим пакетам.


## Пакет `spentenergy` – расчётная логика

Пакет содержит **экспортируемые** функции для вычислений, используемые другими пакетами. Все они уже знакомы по предыдущей версии, но теперь вынесены в отдельный пакет и доступны глобально.

- **`Distance(steps int, height float64) float64`**  
  Рассчитывает дистанцию в километрах:  
  длина шага = `height * stepLengthCoefficient` (коэффициент `0.45`), затем `steps * длина шага / 1000`.

- **`MeanSpeed(steps int, height float64, duration time.Duration) float64`**  
  Вычисляет среднюю скорость (км/ч). Если `duration <= 0` или `steps < 0`, возвращает `0`; иначе – `Distance / (duration.Hours())`.

- **`RunningSpentCalories(steps int, weight, height float64, duration time.Duration) (float64, error)`**  
  Проверяет корректность входных параметров (положительные значения), вычисляет `MeanSpeed`, переводит `duration` в минуты и возвращает калории по формуле:  
  `(weight * meanSpeed * minutes) / 60`.  
  Возвращает ошибку при некорректных данных.

- **`WalkingSpentCalories(steps int, weight, height float64, duration time.Duration) (float64, error)`**  
  Аналогична беговой версии, но итоговое количество калорий умножается на **корректирующий коэффициент** `walkingCaloriesCoefficient` (например, `0.5`), чтобы учесть меньшую интенсивность ходьбы.


## Пакет `personaldata` – данные пользователя

Здесь определена **структура `Personal`** с полями:

- `Name string` – имя пользователя.
- `Weight float64` – вес в килограммах.
- `Height float64` – рост в метрах.

Для этой структуры реализован **метод**:

- **`Print()`** – выводит на экран имя, вес и рост в удобочитаемом формате:

```
Имя: <Name>
Вес: <Weight>
Рост: <Height>
```

Эта структура будет **встраиваться** в структуры тренировок и прогулок, что даёт им доступ к данным пользователя и методу `Print()`.


## Пакет `trainings` – обработка тренировок

Пакет отвечает за разбор строк с данными о тренировках и формирование развёрнутого отчёта.

### Структура `Training`

Содержит поля:

- `Steps int` – количество шагов.
- `TrainingType string` – тип тренировки (например, `"Бег"` или `"Ходьба"`).
- `Duration time.Duration` – продолжительность.
- Встроенная структура `personaldata.Personal` – данные пользователя (имя, вес, рост).

### Методы

- **`Parse(datastring string) error`** (приёмник `*Training`)  
  Парсит строку формата `"3456,Ходьба,3h00m"`:
  - разбивает по запятой;
  - проверяет, что частей ровно три;
  - преобразует шаги в `int` и сохраняет;
  - сохраняет тип тренировки;
  - преобразует длительность в `time.Duration` и сохраняет.  
  При любой ошибке возвращает её.

- **`ActionInfo() (string, error)`** (приёмник `Training`)  
  Используя данные структуры, вычисляет дистанцию (`Distance`), среднюю скорость (`MeanSpeed`) и калории (вызывая `RunningSpentCalories` или `WalkingSpentCalories` в зависимости от `TrainingType`).  
  Формирует и возвращает строку вида:

```
Тип тренировки: Бег
Длительность: 0.75 ч.
Дистанция: 10.00 км.
Скорость: 13.34 км/ч
Сожгли калорий: 18621.75
```

Если тип тренировки неизвестен – возвращает ошибку `"неизвестный тип тренировки"`.


## Пакет `daysteps` – обработка прогулок

Аналогичен пакету `trainings`, но предназначен для **дневной активности** (прогулок).

### Структура `DaySteps`

Содержит поля:

- `Steps int` – количество шагов.
- `Duration time.Duration` – длительность прогулки.
- Встроенная `personaldata.Personal` – данные пользователя.

### Методы

- **`Parse(datastring string) error`** (приёмник `*DaySteps`)  
  Парсит строку формата `"678,0h50m"`:
  - разбивает по запятой (должно быть 2 части);
  - преобразует шаги в `int`;
  - преобразует длительность в `time.Duration`.  
  Возвращает ошибку при некорректном формате.

- **`ActionInfo() (string, error)`** (приёмник `DaySteps`)  
  Вычисляет дистанцию через `Distance` и калории через `WalkingSpentCalories`.  
  Возвращает строку вида:

```
Количество шагов: 792.
Дистанция составила 0.51 км.
Вы сожгли 221.33 ккал.
```

Если расчёт калорий завершился ошибкой – возвращает пустую строку и ошибку.


## Пакет `actioninfo` – универсальный интерфейс

Этот пакет обеспечивает **единообразную обработку** любых активностей, поддерживающих парсинг и формирование отчёта.

### Интерфейс `DataParser`

Объявляет два метода, которые уже реализованы в структурах `Training` и `DaySteps`:

```go
type DataParser interface {
    Parse(datastring string) error
    ActionInfo() (string, error)
}
```

Благодаря этому структуры `Training` и `DaySteps` неявно реализуют интерфейс `DataParser`.

### Функция `Info(dataset []string, dp DataParser)`

Принимает слайс строк с данными и экземпляр любой структуры, удовлетворяющей интерфейсу `DataParser`.  
Алгоритм:

- Для каждой строки из `dataset`:
  - вызывает `dp.Parse()` – если ошибка, логирует её и переходит к следующей строке;
  - вызывает `dp.ActionInfo()` – если ошибка, логирует её, иначе выводит полученную строку.

Таким образом, одна и та же функция `Info` может обрабатывать как массив строк с тренировками (с переданным экземпляром `Training`), так и массив строк с прогулками (с `DaySteps`). Это демонстрирует **полиморфизм** и силу интерфейсов в Go.


## Ключевые особенности новой версии

- **Чёткое разделение ответственности** – каждый пакет занимается своей задачей (расчёты, данные пользователя, парсинг, интерфейс).
- **Использование структур и встраивания** – данные пользователя и методы (например, `Print`) наследуются структурами тренировок и прогулок.
- **Методы, а не функции** – парсинг и формирование отчёта теперь привязаны к конкретным типам данных, что упрощает передачу параметров.
- **Интерфейс `DataParser`** – позволяет обрабатывать разные типы активностей через общий механизм, без привязки к конкретному типу.
- **Обработка ошибок** – все методы возвращают ошибки, которые логируются на верхнем уровне.


## Итог

Разработанный модуль представляет собой готовую к использованию систему фитнес‑трекинга, построенную на принципах объектно‑ориентированного проектирования в Go. Благодаря продуманной архитектуре, добавление новых типов активностей (например, плавания или велоспорта) потребует лишь создания новой структуры с методами `Parse` и `ActionInfo` – и она автоматически станет совместима с функцией `Info`. Это делает приложение гибким, тестируемым и легко расширяемым.
